# Agent Workflow V2 Implementation Spec

Status: implementation-ready for Slice A only. V1 remains canonical and active.

## Goal

Build a portable, installable V2 beside the existing workflow. Preserve the
quality, authority, verification, and same-reviewer loops that have proved useful
while reducing duplicated instructions, automatic ceremony, and operator-facing
reporting.

## Non-goals

- Do not modify, replace, install, or activate anything under `workflow/`,
  `~/.codex/skills`, `~/.claude/skills`, or the active global kernel.
- Do not migrate current plans, archives, operator preferences, model routing, or
  Claude launchers.
- Do not split or weaken the current review rubric in the first V2 pilot.
- Do not copy every V1 skill before the shared ownership model is validated.
- Do not publish a plugin, marketplace entry, tag, PR, or release.

## Architecture

V2 is a skills-only plugin with four layers:

1. **Portable kernel** — authority, safety, minimum-sufficient shape, route
   selection, verification/review floors, and project-adapter precedence.
2. **Shared authorities** — workflow transitions, planning, testing, review, and
   conditional frontend doctrine. Each rule has one owner.
3. **Thin skills** — phase-specific entry, evidence, output, and stop conditions.
   They reference shared authorities instead of copying them.
4. **Adapters** — repo facts and optional host capabilities. They may narrow
   behavior but cannot widen kernel approval, independence, or review rules.

The beta uses `v2-` skill names so it can coexist with V1 without ambiguous
invocation.

## Workflow semantics

The available phase graph is:

```text
plan
  -> explore, when the approach is genuinely open
  -> spike, when one load-bearing bet needs a disposable proof
  -> spec
  -> inner spec review <-> revision
  -> outer spec review <-> revision, when positive risk selects it
  -> implementation
  -> inner implementation review <-> patch
  -> outer implementation review <-> patch, when positive risk selects it
  -> complete
```

This is not a mandatory linear pipeline. The operator selects movement between
phases; same-reviewer revision loops proceed autonomously after selection.

### Routes

- **Fast:** clear, local, reversible change with one focused falsifying proof;
  implementation plus inner review.
- **Standard:** durable spec, inner spec review, implementation, and inner
  implementation review.
- **Assured:** explore/spike when needed, plus risk-selected outer spec and
  implementation reviews for consequential surfaces.

Outer review is positively selected for hard-to-reverse architecture/product
policy; contract/API/schema; persisted lifecycle/migration/data-loss;
auth/security/identity; provider/dependency/toolchain; cross-system rollout;
material unproven bets; an inner finding establishing a material defect on those
surfaces; or an operator request.

## Shared handoff envelope

Every phase starts from the same semantic envelope plus its minimum required
payload:

```text
Work item: stable ID, human name, source, repository
Goal / non-goals: observable outcome and exclusions
Scope: branch, base/tip or files, checkout owner and isolation state
Acceptance: behaviors that must hold
Evidence: exact commands/results and the revision/artifacts they prove
Risk / remaining checks: stale, blocked, operator-only, or unselected
```

Phase payloads initially preserve all required V1 kickoff fields. A field may be
removed only after its owning rule is identified and a representative pilot shows
no lost safeguard.

## Implementation slices

### Slice A — Isolated package and routing foundation

Create an inactive `agent-workflow-v2` plugin containing:

- a valid `.codex-plugin/plugin.json`;
- `references/KERNEL.md`, the portable runtime authority loaded by V2 skills;
- `references/WORKFLOW.md`, the phase graph, route selector, pause rules, and
  delegation boundary;
- `templates/repo-adapter.md`, containing only project facts/capabilities;
- `skills/v2-plan-next/SKILL.md`, a thin beta planning entrypoint;
- corresponding UI metadata generated by the skill initializer.

Slice A does not install the plugin or modify a marketplace.

Acceptance criteria:

1. V1 files and installed skill/kernel paths are unchanged.
2. The plugin validates with the bundled plugin validator.
3. `v2-plan-next` validates with the bundled skill validator and contains no
   unfinished scaffold text.
4. `v2-plan-next` loads the V2 kernel and workflow authority, owns program scope
   and sequencing, delegates only bounded evidence questions, prohibits nested
   delegation, and does not implement or certify code. Until a selected phase's
   V2 entrypoint, authority, and payload exist, it reports the missing component
   and “phase not implemented” without emitting a kickoff or dispatching partial
   semantics.
5. Project facts, model/provider choices, trackers, branches, commands, and plan
   locations are absent from the portable kernel and resolved through adapters.
6. Missing V2 kernel or workflow references cause the skill to stop rather than
   silently falling back to partial semantics.

Verification:

- plugin validation;
- skill validation;
- `git diff --check`;
- diff-scope check proving only this spec and `agent-workflow-v2/**` changed on
  the V2 branch;
- one fresh inner review of the exact Slice A range.

### Slice B — Planning evidence phases

Add thin `v2-explore`, `v2-spike`, and `v2-spec` skills plus the canonical
planning authority. Preserve compact durable outputs once a formal phase is
invoked, but do not activate those phases from casual questions.

### Slice C — Review and testing authorities

Port `TESTING.md`, `REVIEW_RUBRIC.md`, and the shared handoff state machine before
adding thin inner/outer spec and implementation review skills. Keep the full
review rubric intact for the first pilot. Re-review aliases reuse the original
reviewer rather than owning copied policy.

### Slice D — Implementation and completion

Add the implementation entrypoint, minimum-shape recheck, causal verification,
docs-impact decision, compact receipt, and completion routing. Outer-owned
patches return directly to the same outer reviewer.

### Slice E — Optional extensions and pilots

Port `prreview` as a separate, deliberately thorough coworker-PR extension. Add
optional host adapters only after the portable behavior works without them. Run
frozen V1/V2 pilots before any activation or V1 retirement decision.

## Pilot and promotion

Use identical frozen revisions, acceptance criteria, and available evidence for
V1 and V2. Include compact documentation, a normal behavior fix, a test-removal
spike, a persistence/migration change, a CI fresh-runner case, an oversized
lifecycle proposal, a consequential provider/compiler case, and a coworker PR.

Promote only if V2 preserves known defect detection, approval boundaries,
independence, real-boundary testing, and same-reviewer convergence while reducing
unnecessary phase activation, duplicate output, broad reruns, task transitions,
false blockers, and operator corrections.

Rollback is disabling the beta plugin and continuing to use the untouched V1
kernel and skills.
